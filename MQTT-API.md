# ship-driver — MQTT API

**Брокер:** `192.168.69.105:1883`  
**Активный канал:** `boat4` (LoRa CH19, корабль №9)  
**Контроллер:** WB8 (wirenboard-AKEYTVSO)

---

## Устройства MQTT

| Устройство | Топик | Назначение |
|---|---|---|
| `boat1..4` | `/devices/boatN/…` | Оперативный API канала + визуализация |
| `ship_setup` | `/devices/ship_setup/…` | Преднастройка LoRa-модема корабля по проводу (RS485-1) |
| `charger1..N` | `/devices/chargerN/…` | Беспроводные зарядные станции (реле передатчика/магнитов + ток) |

Дашборд `boatN` появляется **только для тех MOD-слотов, где при старте нашёлся LoRa-модем**. На этом контроллере активен только `boat4`.

---

## Доступ

Внешние клиенты (те, что управляют кораблём) подключаются к брокеру `192.168.69.105:1883`. На этом порту видны **только топики корабля** — `/devices/boatN/#`, `/devices/chargerN/#` и `/devices/ship_setup|ship_diag|ship_bus/#` (и на чтение, и на запись). Всё остальное на контроллере (`/devices/system`, `/devices/network`, `wb-*` и т. п.) с этого порта закрыто.

Сам набор топиков и контролов при этом **не менялся** — управление и телеметрия ровно те же, что и раньше; поменялась только область видимости на внешнем порту.

## Контролы boat4

### Чтение (subscribe)

```bash
# подписаться на всю телеметрию
mosquitto_sub -h 192.168.69.105 -t '/devices/boat4/controls/+' -v

# один контрол
mosquitto_sub -h 192.168.69.105 -t '/devices/boat4/controls/mode' -C 1
```

| Контрол | Топик | ro/rw | Значение |
|---|---|---|---|
| `mode` | `/devices/boat4/controls/mode` | ro | `SEARCH` / `SAILING` / `CHARGING` / `IDLE` / `OFF` |
| `enabled` | `/devices/boat4/controls/enabled` | rw | `0` / `1` |
| `ship_number` | `/devices/boat4/controls/ship_number` | rw | `0–65535` — LoRa-адрес корабля, пишется в модем немедленно |
| `battery_current` | `/devices/boat4/controls/battery_current` | ro | A, float · разряд отрицательный · период 5 с в IDLE |
| `battery_voltage` | `/devices/boat4/controls/battery_voltage` | ro | В · напряжение АКБ (~8 В) · вместе с током |
| `battery_temperature` | `/devices/boat4/controls/battery_temperature` | ro | °C · 5 мин в IDLE, 10 с в CHARGING |
| `charge_level` | `/devices/boat4/controls/charge_level` | ro | % заряда |
| `input_voltage` | `/devices/boat4/controls/input_voltage` | ro | В · входное напряжение ИБП · период 5 с (читается вместе с током) |
| `rssi` | `/devices/boat4/controls/rssi` | ro | дБм · RSSI LoRa‑линка активного борта (E220 packet‑byte) |
| `comms_errors` | `/devices/boat4/controls/comms_errors` | ro | сырых промахов чтения за скользящие 5 мин |
| `link_quality` | `/devices/boat4/controls/link_quality` | ro | % успешных чтений за 5 мин (100 = идеал) |
| `charge_setpoint` | `/devices/boat4/controls/charge_setpoint` | ro | мА · текущая уставка тока заряда, которую держит тепловой регулятор (300…2000) |
| `link_score` | `/devices/boat4/controls/link_score` | ro | 0…100 · общая оценка связи: свёртка `read_failures` (вес 0.45), `link_quality` (0.25), `rssi` (0.20), `lat_p95` (0.10); сверху ограничена «оценкой потерь + 20», чтобы реальные потери всегда тянули вниз. ≥90 отлично, 75–90 хорошо, 50–75 слабо, <50 плохо |
| `read_failures` | `/devices/boat4/controls/read_failures` | ro | отказов чтения **после всех повторов** за 5 мин = реально потерянные данные |
| `err_timeout` | `/devices/boat4/controls/err_timeout` | ro | отказов «не пришло ни байта» за 5 мин |
| `err_frame` | `/devices/boat4/controls/err_frame` | ro | отказов «обрывок / чужой кадр / битый CRC» за 5 мин |
| `retry_fixed` | `/devices/boat4/controls/retry_fixed` | ro | промахов, вылеченных повтором, за 5 мин |
| `course` | `/devices/boat4/controls/course` | ro | ° · курс борта (−180…180) с датчика WT901C485; публикуется только если датчик есть на этом борту |
| `lat_p95` | `/devices/boat4/controls/lat_p95` | ro | мс · латентность чтения, 95‑й перцентиль |
| `back_left` / `front_left` / `back_right` / `front_right` | `/devices/boat4/controls/{name}` | rw | `0–100` делений газа: `0` = выход снят, `1` = холостой, `100` = полный. Дробные принимаются. См. «Газ моторов» ниже |
| `nav_lights` / `morse_lamp` / `deck_lights` / `cabin_light1` / `cabin_light2` | `/devices/boat4/controls/{name}` | rw | `0–100` % |
| `mp3_track` | `/devices/boat4/controls/mp3_track` | rw | `0` = стоп, `1–15` = трек |
| `mp3_volume` | `/devices/boat4/controls/mp3_volume` | rw | `0–30` |

> **Важно:** контролы моторов, света и батареи видны на дашборде, только пока канал онлайн (режимы SAILING / CHARGING / IDLE). В SEARCH и OFF они прячутся и возвращаются, когда борт снова выходит на связь.

### Газ моторов: деления и частота

Ползунок мотора — **0…100**, и это не проценты скважности, как было раньше.
Смысл делений:

| деление | что происходит |
|---|---|
| `0` | выход снят совсем: скважность 0, ESC не видит сигнала |
| `1` | холостой ход, импульс 1000 мкс (прежняя скважность 40) |
| `2` | страгивание, импульс 1047 мкс — измерено, ниже вал стоит |
| `100` | полный, импульс 2000 мкс (прежняя скважность 80) |

Внутри драйвера газ задаётся **частотой** при постоянной скважности 60 %:
импульс = 0.60 · 1e6 / f, поэтому деления 1…100 это частоты 600…300 Гц.
Смысл замены: скважность модуль принимает только целыми процентами, то есть
шаг импульса был 25 мкс при 400 Гц; частота задаётся целыми герцами, и шаг
стал 10.1 мкс на деление. **Дробные значения принимаются** (`30.5`), железо
различает около 2.4 мкс — примерно четверть деления.

Прежняя шкала 40…80 **больше не действует**: значение 40 теперь означает не
холостой ход, а импульс 1394 мкс. Клиенты, которые её помнят, надо обновить.

Ход ползунка **нелинейный**. Деление 1 — холостой (1000 мкс, ESC взведён, вал стоит),
деление 2 — `pulse_start_us` = 1047 мкс, **измеренная точка страгивания**, дальше до
`pulse_top_us` идёт степенная кривая `x**throttle_gamma`. При `gamma` = 1.5 шаг растёт от
1 мкс у страгивания до 15 мкс у полного газа, и рабочая зона до 1400 мкс занимает половину
ползунка (51 деление) вместо 37 при линейной шкале. `gamma` = 1.0 возвращает линейную.

Круче 1.5 идти бессмысленно: шаг импульса опускается ниже 1.67 мкс, которые железо различает
у холостого, и деления начинают давать одну и ту же частоту — ползунок растёт, управление нет.

Точка страгивания **измерена**, а не оценена: стенд 25.08 без винтов — на 1037 мкс один вал
дёргается (зацепление, не вращение), на 1042 крутятся два, на 1048 все четыре. Прежде деления
2…14 лежали внутри мёртвой зоны и не давали ничего. Разрыв между делениями 1 и 2 намеренный:
это стык «стоит / пошёл», дробные значения между ними смысла не имеют.

Оговорка: пороги четырёх моторов разъехались примерно на 10 мкс, поэтому у самого низа шкалы
два движителя тянут, а два ещё нет — на минимальном газу катер будет уводить. Пол общий на все
каналы; свой пол на канал это вылечило бы, но выбран общий.

Свет частоту не использует: у световых каналов яркость — это по-прежнему
скважность при 400 Гц.

Пределы задаются в конфиге (`main.limits`): `throttle_max`, `pulse_idle_us`,
`pulse_start_us`, `pulse_top_us`, `throttle_gamma`, `motor_duty`. Частота вне полосы, посчитанной из них, для
драйвера означает «модуль ребутнулся» и вызывает полную реинициализацию с
переармом ESC.

### Запись (publish → `/on`)

Любая команда записи публикуется в топик `/devices/boat4/controls/<ctrl>/on`.

```bash
# мотор вперёд-вправо на деление 60 (импульс 1596 мкс, частота 376 Гц)
mosquitto_pub -h 192.168.69.105 \
  -t '/devices/boat4/controls/front_right/on' \
  -m 60

# ходовые огни на 100 %
mosquitto_pub -h 192.168.69.105 \
  -t '/devices/boat4/controls/nav_lights/on' \
  -m 100

# включить трек 3 на громкости 20
mosquitto_pub -h 192.168.69.105 -t '/devices/boat4/controls/mp3_volume/on' -m 20
mosquitto_pub -h 192.168.69.105 -t '/devices/boat4/controls/mp3_track/on'   -m 3

# переключить канал на корабль №15 (пишет адрес в LoRa-модем немедленно)
mosquitto_pub -h 192.168.69.105 \
  -t '/devices/boat4/controls/ship_number/on' \
  -m 15

# остановить все моторы (холостой ход = деление 1; 0 снял бы сигнал с ESC совсем)
for m in front_left front_right back_left back_right; do
  mosquitto_pub -h 192.168.69.105 \
    -t "/devices/boat4/controls/${m}/on" \
    -m 1
done

# выключить канал (порт закрывается, LoRa переходит в config-mode)
mosquitto_pub -h 192.168.69.105 \
  -t '/devices/boat4/controls/enabled/on' \
  -m 0
```

> **Режим ничего не запрещает.** Он вычисляется ИЗ состояния (газ выше холостого, или команда мотором моложе 30 с), а не разрешает команды. В `IDLE` команда проходит так же, как в `SAILING` — и именно она переводит режим в `SAILING`, а не наоборот.
>
> В **SEARCH и OFF** борта на связи нет, поэтому команда **отклоняется явно**: в журнал идёт строка `команда ОТКЛОНЕНА: <контрол>=<значение>, борт не на связи`, на контроле выставляется `meta/error = "w"`, а значение возвращается к тому, что реально задано в драйвере. Молча команда не теряется никогда.
>
> А вот `mp3_track` и `mp3_volume` режим в SAILING **не** переключают — так задумано.

## Корабли — `shipN`

Кроме радиоточек `boatN` драйвер публикует устройства по **кораблям**: `ship1 … ship10`
(номера из `ships.list`). Смысл в истории: канал обслуживает то один борт, то другой,
поэтому график «ток батареи по boat4» смешал бы разные корабли. `shipN` повторяет физику
того канала, который **сейчас** обслуживает этот корабль, и история копится по кораблю.

| Где | Что лежит |
|---|---|
| `shipN` | физика: `battery_current`, `battery_voltage`, `battery_temperature`, `charge_level`, `input_voltage`, моторы, свет, `course` и весь блок инклинометра. Плюс `active` = 1 у того корабля, что сейчас на канале (у остальных 0, значения остаются последними известными) |
| `boatN` | радиометрики: `rssi`, `comms_errors`, `link_quality`, `read_failures` — это свойство радиоточки, а не корабля |

`boatN` не менялся, это внешний API: **команды по-прежнему идут в `boatN`**.

⚠ Каждое устройство должно быть перечислено в `/etc/mosquitto/acl/ship.conf` строкой
`topic readwrite /devices/<имя>/#`. Публикация в тему вне ACL для MQTT 3.1.1 означает,
что брокер **отключает клиента**, и драйвер начинает молча ходить по кругу
переподключений — в журнале `mosquitto` это `Quota exceeded`, а в журнале драйвера видно
только повторяющееся `declare:`. С версии, добавившей панель `pwm_setup`, недостающие
строки дописывает `postinst`, а сам драйвер при четырёх переподключениях за минуту пишет
в журнал подсказку со списком нужных устройств.

## Панель `pwm_setup` — начальная настройка модулей PWM8A04

Отдельная вкладка «PWM8A04 Setup (RS485-1)» для настройки модулей **по проводу**, до
установки на борт. Свежий модуль приходит с заводским адресом **1**; регистр **253** —
адрес устройства, **254** — код скорости (`3` = 9600).

| Контрол | Что делает |
|---|---|
| `address` | по какому адресу спрашиваем (1..247) |
| `read` | читает регистр адреса по проводу (RS485-1, Modbus, 9600) — одна транзакция, ничего лишнего |
| `new_address` | какой адрес записать |
| `write` | пишет регистр 253, ждёт секунду (адрес применяется сразу, модуль при этом перезагружается и теряет частоты со скважностями — драйвер всё равно выставит их при `init_ship`), затем проверяет чтением **на новом адресе** и отдельно проверяет, что старый замолчал |
| `status` | исход словами |

Если после записи **старый адрес продолжает отвечать**, значит на нём сидел не один
модуль — об этом сказано прямо в `status`. Так было 11.08: три свежих модуля стояли на
заводском адресе 1 разом, и запись приняли все три.

Обе панели настройки ходят в один порт RS485-1 через общую очередь, поэтому доступ к нему
последовательный.

## Режимы (mode state machine)

| Режим | Когда | Дашборд |
|---|---|---|
| **SEARCH** | нет связи, зондирует ~0.8 с | свёрнут |
| **SAILING** | команда < 30 с назад | полный |
| **CHARGING** | 30 с без команд + ток > 0 | полный |
| **IDLE** | 30 с без команд + ток ≤ 0 | полный |
| **OFF** | `enabled = 0` | свёрнут |

**Что происходит при выходе в онлайн:** все DUTY → 0, затем FREQ → 400 Гц, моторы → 40, свет → 0.  
**В режиме OFF:** GPIO MODn=1 переводит LoRa в config-mode. Состояние сохраняется в `/etc/ship-driver-state.json`.

### Матрица периодов опроса

| Параметр | SEARCH | SAILING | IDLE | CHARGING |
|---|---|---|---|---|
| `battery_current` | ~0.8 с | 5 с | **5 с** ✓ | 5 с |
| `battery_temperature` | — | 5 мин | 5 мин | 10 с |
| `charge_level` | — | 5 мин | 5 мин | 1 мин |
| `motors` | — | 1 мин | 5 мин | 1 мин |
| `lights` | — | 1 мин | 5 мин | 1 мин |

✓ подтверждено live: `13:53:24 → :29 → :34 → :40` (интервалы 5–6 с с учётом Modbus over LoRa overhead)

## Зарядные станции — `chargerN`

Опрашиваются по Modbus RTU через **TCP-шлюз** (EBYTE serial server, `host:port` задаётся в конфиге)
— отдельно от корабельной LoRa-шины. Управление — публикацией в `/on`, период опроса примерно 3 с.

| Контрол | Топик | ro/rw | Значение |
|---|---|---|---|
| `transmitter` | `/devices/chargerN/controls/transmitter` | rw | `0`/`1` — передатчик XKT-801 |
| `magnets` | `/devices/chargerN/controls/magnets` | rw | `0`/`1` — магниты фиксации |
| `transmitter_current` | `/devices/chargerN/controls/transmitter_current` | ro | ток передатчика, А (WB-MAI6 = падение на шунте / сопротивление) |
| `charge_link` | `/devices/chargerN/controls/charge_link` | ro | % · качество посадки катушек по просадке `input_voltage`: 100 = напряжение у холостого (≈12.7 В минус 0.35 В на ампер заряда), 0 = недобор 2 В и больше. Не зависит от состояния батареи; «нет данных», если борта на паду нет |

```bash
# включить передатчик и магниты на станции 1
mosquitto_pub -h 192.168.69.105 -t '/devices/charger1/controls/transmitter/on' -m 1
mosquitto_pub -h 192.168.69.105 -t '/devices/charger1/controls/magnets/on'     -m 1

# ток передатчика
mosquitto_sub -h 192.168.69.105 -t '/devices/charger1/controls/transmitter_current' -C 1
```

> Реле WB-MRM2-mini здесь нормально-замкнутые, поэтому в конфиге зарядки для каждого выхода включён
> `invert` — чтобы `1` означало «включено». При старте драйвер только показывает фактическое
> состояние реле, ничего не переключая.
